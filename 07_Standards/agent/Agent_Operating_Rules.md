# قواعد عمل وكيل تطوير AITOS (AITOS Dev Agent Operating Rules)

تحدد هذه الوثيقة القواعد الصارمة التي يجب أن يلتزم بها AITOS Dev Agent أثناء تنفيذ مهامه.

## 1. مبدأ "عدم التدمير" (Non-Destructive Principle)
*   لا يجوز للوكيل حذف أي ملفات معمارية معتمدة (00_Architecture) دون موافقة صريحة من المستخدم.
*   لا يجوز للوكيل تعديل مواصفات الوحدات (01_Modules) إلا لإضافة تفاصيل تنفيذية أو إصلاح أخطاء واضحة، ويجب أن يكون ذلك عبر Pull Request.

## 2. إدارة الفروع والدمج (Branching & Merging)
*   يجب على الوكيل دائماً إنشاء فرع جديد (Feature Branch) لكل مهمة.
*   لا يجوز للوكيل الرفع (Push) مباشرة إلى فرع `main`.
*   يجب أن يفتح الوكيل Pull Request (PR) لكل تغيير، مع شرح مفصل لما تم تنفيذه.

## 3. جودة التوثيق (Documentation Standards)
*   يجب أن يتبع الوكيل معايير التوثيق المحددة في `07_Standards/Documentation_Standards.md`.
*   يجب تحديث `CHANGELOG.md` و `PROJECT_STATUS.md` تلقائياً عند كل عملية دمج ناجحة.

## 4. التواصل مع المستخدم
*   يجب على الوكيل تقديم تقارير دورية عن المهام المنجزة والمهام قيد التنفيذ.
*   في حال مواجهة تعارضات أو مشاكل تقنية، يجب على الوكيل التوقف وطلب التوجيه من المستخدم.

## 5. حدود العمل (Scope of Work)
*   يعمل الوكيل حصرياً داخل حدود مستودع AITOS والمجلدات المسموح له بها.
*   لا يجوز للوكيل الوصول إلى أي موارد خارجية غير مصرح بها.
